## フォルダ構成

## 1. 文書概要

|項目|内容|
|---|---|
|対象システム|LiveCloud|
|作成日|2026-08-19|
|対象|フロントエンド、設計ドキュメント、GitHub Pagesデプロイ設定|

本書は、LiveCloudリポジトリのフォルダと主要ファイルの役割を定義する。画面単位のコンポーネントとスタイルは原則として同じフォルダに配置し、データアクセス・バックアップの共通処理は `src/lib` に集約する。

## 4. 配置ルール

### 4.1 画面

画面コンポーネントは `src/pages/<画面名>/` に置き、画面固有のスタイルは同じフォルダの `<画面名>.css` に置く。

|画面|配置|主な責務|
|---|---|---|
|ホーム|`pages/Home/`|検索、アーティスト一覧、主要画面への導線。|
|アーティスト追加|`pages/AddArtist/`|アーティスト名・プロフィール画像の登録。|
|アーティスト詳細|`pages/ArtistDetail/`|ライブ一覧、基本情報、削除。|
|ライブ追加|`pages/AddLiveBasic/`、`pages/AddLiveDetail/`|基本入力と詳細入力の2段階登録。|
|ライブ詳細|`pages/LiveDetail/`|ライブ記録の閲覧、評価更新、削除。|
|ライブ編集|`pages/EditLive/`|基本情報、セットリスト、写真、メモの編集。|
|統計|`pages/Stats/`|サマリー、推移、アーティスト別集計。|
|設定|`pages/Settings/`|完全バックアップ、復元、保存状況の表示。|

`AddLivePhoto/` と `Statistics/` は将来の画面分割・機能拡張を見据えた配置であり、現在の主要ルートはそれぞれ `AddLiveDetail/` と `Stats/` が担当する。

### 4.2 共通UI

複数画面で使用する表示部品は `src/components/` に置く。部品固有のスタイルは、`<部品名>.module.css` または `<部品名>.css` として部品と同じフォルダに配置する。

|部品|配置|役割|
|---|---|---|
|`AppUpdate`|`components/AppUpdate/`|新しいService Workerを検知した際の更新通知。|
|`ArtistCard`|`components/ArtistCard/`|アーティスト一覧のカード表示。|
|`BottomNavigation`|`components/BottomNavigation/`|ホーム、統計、追加、設定の画面移動。|
|`FloatingButton`|`components/FloatingButton/`|アーティストまたはライブの追加導線。|
|`Header`|`components/Header/`|アプリ名・通知アイコンを含むホームヘッダー。|
|`SearchBar`|`components/SearchBar/`|アーティスト名のキーワード検索。|

### 4.3 データアクセスと型

- Supabaseクライアントの初期化は `src/lib/supabase.ts` だけで行う。
- DB・Storageをまたぐ完全バックアップと復元は `src/lib/backup.ts` に置く。
- 表示用の共通データ型は `src/types/` に置く。
- 画面からSupabaseを利用する場合も、環境変数やクライアント生成処理を画面内へ重複して書かない。

## 5. 設計書 `docs/` とサイト `docs-site/`

`docs/` は設計書の正本である。`docs-site/` はBlumeを用いて `docs/` を閲覧用の静的サイトへ変換するための設定を保持する。

|対象|編集方針|
|---|---|
|`docs/*.md` / `docs/*.mdx`|設計内容を更新する。|
|`docs/images/screens/`|画面一覧で参照する画面キャプチャを配置する。|
|`docs-site/blume.config.ts`|設計書サイトのタイトル、テーマ、コンテンツルート、出力設定を変更する場合のみ編集する。|
|`docs-site/dist/`|ビルド生成物。編集しない。|

設計書サイトの確認には `npm run docs:dev`、静的ビルドには `npm run docs:build` を使用する。すでに開発サーバーが起動している場合は、隔離モードでのビルド検証を行う。

## 6. ビルド・公開に関係するファイル

|ファイル・フォルダ|役割|
|---|---|
|`package.json`|`dev`、`build`、`lint`、`docs:*` のnpmスクリプトと依存関係を定義する。|
|`vite.config.ts`|GitHub Pages用の`base`、Reactプラグイン、PWAマニフェスト、Service Worker生成を設定する。|
|`public/`|PWAマニフェストやHTMLから参照する静的アイコンを配置する。|
|`.github/workflows/deploy.yml`|`main`ブランチへのpushを契機にアプリをビルドし、GitHub Pagesへデプロイする。|
|`.env.local`|`VITE_SUPABASE_URL`と`VITE_SUPABASE_PUBLISHABLE_KEY`をローカルで設定する。リポジトリへ含めない。|

## 7. 変更時の判断基準

|変更内容|配置先|
|---|---|
|新しいルート画面|`src/pages/<画面名>/`|
|複数画面で使うUI|`src/components/<部品名>/`|
|外部API・Storage・データ変換の共通処理|`src/lib/`|
|画面をまたいで共有するデータ型|`src/types/`|
|画面専用の画像・既定素材|`src/assets/`|
|ビルド時にそのまま配信するファイル|`public/`|
|機能・画面・データ構造の仕様|`docs/`|

新しい機能を追加する際は、画面、共通部品、データアクセス、型、設計書のどこに責務を置くかを先に決め、既存の責務と重複しない場所へ配置する。
